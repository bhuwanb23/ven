# Plan: End-to-End Testing & Bug Finding for ven

## Goal
Build ven from source, test ALL commands end-to-end in the `example/` folder, find bugs/issues, and test upgrade/version scenarios.

## Phase 1: Build ven from source

```bash
cargo build --release --bin ven --bin ven-launcher
```

Verify binaries exist at `target/release/ven.exe` and `target/release/ven-launcher.exe`.

## Phase 2: Smoke test global commands (no project needed)

Test from repo root or a temp directory:

| Command | What to check |
|---------|---------------|
| `ven --version` | Prints version correctly |
| `ven --help` | Shows all subcommands |
| `ven list` | Lists installed runtimes |
| `ven path show` | Shows VEN_HOME path |
| `ven doctor` | Diagnoses install health |
| `ven shell hook powershell` | Outputs valid PS hook script |

## Phase 3: Per-language round-trip in example/

For each language (node, bun, python, ruby, java, deno, go, rust):

1. `ven status` — shows runtime + config
2. `ven status --verbose` — adds disk usage
3. `ven status --json` — valid JSON output
4. `ven check-add <pkg>` — compatibility check (no install)
5. `ven add <pkg>` — installs package, updates manifest
6. `ven graph` — shows dependency graph
7. `ven why <pkg>` — reverse dependency lookup
8. `ven upgrade --dry-run` — preview upgrades
9. `ven remove <pkg> --force` — removes package
10. `ven init` — in a fresh temp dir, creates ven.toml

## Phase 4: Edge cases & error scenarios

| Test | Expected |
|------|----------|
| `ven add nonexistent-pkg-xyz` | Graceful error, not a panic |
| `ven add` with no args in non-interactive | Helpful error message |
| `ven remove pkg-not-installed --force` | Graceful "not found" error |
| `ven sync` with no ven.lock | Helpful error |
| `ven lock` in non-node project | Appropriate error or no-op |
| `ven check` with no network | Offline fallback or clear error |
| `ven scan --ghosts` in empty project | No ghosts found |
| `ven why pkg-not-installed` | "not found" message |
| `ven docs nonexistent-pkg` | Error, not panic |
| `ven upgrade` with nothing to upgrade | "Already up to date" |
| Running ven from a directory with no ven.toml | Walks up or shows error |
| `ven add` with invalid version spec | Clear error |
| `ven install <lang> <bad-version>` | Clear error, not panic |

## Phase 5: Version upgrade test

1. Check current version: `ven --version`
2. Test `ven update --check` (check for updates without applying)
3. If a newer version exists, test `ven update` to upgrade
4. Verify new version works: `ven --version`
5. Test rollback: can we go back?

## Phase 6: Lock & sync round-trip

1. In `example/node/`: `ven add express`
2. `ven lock` — generates ven.lock
3. Verify ven.lock has integrity hashes
4. Tamper with ven.lock (change a hash)
5. `ven sync --check` — should detect tampering
6. `ven sync` — should reinstall from lock

## Phase 7: Document all bugs found

For each bug:
- Command that triggered it
- Expected vs actual behavior
- Severity (critical/high/medium/low)
- Reproduction steps
- Suggested fix
